# 팀 논문 공유 시스템 — 설계·구현 기록

## 1. 목표

연구원에게 가장 중요한 건 논문 읽기. 각자 읽은 좋은 논문을 팀원들과 매주 공유하는 흐름을 만든다.
AI를 개인용이 아니라 **팀을 위해** 쓰는 방법을 찾는 게 출발점.

- 팀원 각자 Claude를 구독 중 → 요약·검색은 각자 Claude로 (추가 LLM 비용 없음)
- 팀 규모: 당장은 5명 안팎
- 우리 팀 외 다른 팀도 쓸 수 있게 범용적으로 설계

---

## 2. 최종 구조

| 역할 | 어디서 | 방식 |
|---|---|---|
| 올리기 | 각자 Claude | `paper-share` 스킬 → 우리 MCP 서버 `share_paper` |
| 찾기 | 각자 Claude | 우리 MCP 서버 `search_papers` |
| 저장·조회 | 팀 노션 DB | MCP 서버가 **노션 내부 통합 토큰 하나**로 접근 |
| 주간 공유 | Teams 채널 | 스케줄 함수 → Teams Workflows 웹훅 (구현 중) |
| 실행 환경 | Supabase Edge Functions | 서버리스. Supabase는 실행용으로만, 데이터는 노션 |

MCP 도구 4개: `find_paper`, `get_options`, `share_paper`, `search_papers` (상세는 `notion-db-design.md`)

---

## 3. 주요 결정과 이유

**저장소: 노션 (수파베이스 DB 대신)**
- 팀원들이 평소 보는 곳이 노션 → 별도 조회 UI 불필요, 뷰로 필터·그룹 가능
- 잃는 것: 제약조건(중복 방지, 필수값) 없음 → MCP 서버 코드가 대신 검사
- 저장소만 바꾸면 되는 구조라 나중에 수파베이스 DB로 옮기기 쉬움

**팀원이 노션에 직접 MCP 연결하지 않음 → 자체 MCP 서버 경유**
- 팀 노션에 MCP 연결은 노션 소유자만 가능, 아니면 유료 플랜이 필요함을 확인
- 해결: 노션 소유자가 내부 통합 토큰을 **1회** 만들어 공유 DB에만 연결 → MCP 서버가 그 토큰 사용
- 팀원은 우리 MCP 서버만 커스텀 커넥터로 연결. 팀원 식별은 서버가 발급한 API 키로 함

**공유자: Notion Person이 아니라 Multi-select**
- 구현 중 워크스페이스에 개별 연구원 계정이 없고 공용 로그인 하나만 있다는 것을 발견
- 신원 식별은 어차피 API 키 → 이름 매핑이 서버 책임이라, Person 속성 없이도 동작하도록 설계를 바로 수정함

**논문 1개 = 노션 페이지 1개**
- 요약 5항목(연구 질문, 방법, 핵심 결과, 한계, 시사점)은 본문, 한줄요약·태그·연구주제·추천코멘트는 속성
- 같은 논문을 두 번째 사람이 올리면: 요약 새로 만들지 않고 추천코멘트 줄 추가 + 공유자 추가 + 최근공유일 갱신

**태그: 고정 목록 없음, AI가 생성**
- 같은 뜻이 흩어지는 문제(`fhir` / `hl7 fhir`) → 만들기 전 `get_options`로 기존 태그 확인 후 재사용

**관련연구주제: 사용자가 지정 (태그와 별개)**
- Teams 다이제스트에 "관련연구주제: ~"로 노출되면 팀원이 바로 관련성을 알 수 있게
- Select 속성, 미지정 시 `기타`. AI가 추측해서 채우지 않음

**추천코멘트: 필수, AI 작성 금지**
- AI 요약보다 "내가 왜 팀에 추천하는지" 한 줄이 더 가치 있다는 판단

**검색은 Teams 봇이 아니라 각자 Claude에서**
- 서버리스 유지, 학교 Teams의 외부 연동 제약 회피, LLM 비용은 각자 구독으로 해결

**Teams는 주간 다이제스트 게시만, 어댑티브 카드 형식**
- Power Automate의 "Teams 웹후크 요청이 수신된 경우" 트리거는 일반 텍스트가 아니라 어댑티브 카드 JSON을 요구함을 구현 중 확인 → 메시지 생성 로직을 어댑티브 카드로 변경
- 기관 Power Automate 환경이 익명 웹훅 호출에 OAuth 인증을 요구해(`DirectApiAuthorizationRequired`) 실제 게시는 보완 필요

## 4. 구현 순서 (실제 진행)

1. 노션에 DB 생성 (`논문 공유`, NINT-Projects/자동화 워크플로우 하위) — 완료
2. MCP 서버 구현 — Supabase Edge Function `paper-share` — 완료, 공유/검색/중복 거절까지 실동작 확인
3. `team_members` 테이블(API 키 해시 → 이름)로 팀원 인증 — 완료
4. `paper-share` 스킬 작성 및 연결 테스트 — 완료 (Claude Code MCP 커넥터로 연결 확인)
5. 주간 다이제스트 함수 `paper-share-digest` — Edge Function과 어댑티브 카드 생성까지 완료, 실제 Teams 게시는 기관 인증 정책 문제로 보완 중
6. (나중) 논문 많아지면 임베딩 기반 의미 검색
