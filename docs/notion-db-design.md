# 논문 공유 — 노션 DB 설계

구조: **논문 1개 = 페이지 1개**

## 0. 전체 구조

| 역할 | 어디서 | 방식 |
|---|---|---|
| 올리기 | 각자 Claude | 스킬 → 우리 MCP 서버 `share_paper` |
| 찾기 | 각자 Claude | 우리 MCP 서버 `search_papers` |
| 저장·조회 | 팀 노션 DB | MCP 서버가 내부 통합 토큰 하나로 접근 |
| 주간 공유 | Teams 채널 | 스케줄 함수 → Teams Workflows 웹훅 |

- MCP 서버와 스케줄 함수는 **Supabase Edge Functions**에서 실행 (서버리스, 맥미니 불필요)
- Supabase는 실행 환경으로만 쓰고, 데이터는 노션에 저장
- LLM 비용: 올리기·찾기는 각자 Claude 구독으로 처리, 서버 쪽엔 LLM 없음

## 1. DB 속성

| 속성 | 타입 | 채우는 주체 | 설명 |
|---|---|---|---|
| 제목 | Title | AI | 논문 원제목 |
| PMID | Text | AI | PMID 또는 DOI 중 하나는 필수 (서버에서 검사) |
| DOI | Text | AI | |
| 링크 | URL | AI | PubMed 또는 DOI 링크 |
| 저널 | Text | AI | |
| 출판연도 | Number | AI | |
| 연구유형 | Select | AI | 옵션 고정 (아래) |
| 관련연구주제 | Select | **사용자** | 옵션은 쓰면서 쌓임. 미지정 시 `기타` |
| 태그 | Multi-select | AI | 옵션 자유 생성, 소문자 |
| 한줄요약 | Text | AI | 표·보드 뷰와 다이제스트에 노출 |
| 추천코멘트 | Text | **사용자** | `이름: 코멘트` 형식, 공유자가 늘면 줄 추가 |
| 공유자 | Multi-select | 서버 | 팀원 이름. 워크스페이스에 개별 노션 계정이 없어 Person 대신 사용 |
| 최근공유일 | Date | 서버 | 새 공유·추가 공유 시 갱신 (다이제스트 기준) |
| 최초공유일 | Created time | 자동 | |

**연구유형 옵션:** RCT, cohort, case-control, cross-sectional, qualitative, mixed-methods, systematic-review, meta-analysis, scoping-review, system-development, methodology, other

> 최초 설계에서는 "공유자"를 Notion Person 속성으로 잡았으나, 실제 워크스페이스에 개별 연구원 계정이 없고 공용 로그인(NINTLab) 하나만 있다는 것을 구현 중에 발견해 Multi-select(이름 텍스트)로 변경함. 신원 식별은 어차피 서버의 API 키 매핑이 담당하므로 노션 계정 유무와 무관하게 동작함.

## 2. 페이지 본문 템플릿

```
## 요약 — {최초 공유자}, {날짜}

### 연구 질문
...
### 방법
연구 설계, 대상/데이터, 분석 방법 또는 모델
### 핵심 결과
...
### 한계
...
### 시사점
...

## 추가 메모
- {이름} ({날짜}): ...        ← 두 번째 이후 공유자가 원할 때만
```

- 요약은 최초 공유자 것 하나만. 이후 공유자는 추천코멘트만 추가하고, 보충할 게 있으면 `추가 메모`에.

## 4. MCP 서버 도구

| 도구 | 입력 | 동작 |
|---|---|---|
| `find_paper` | pmid / doi / title | 이미 있는 페이지면 제목, 공유자, 링크 반환 |
| `get_options` | 없음 | DB의 관련연구주제·태그 옵션 목록 반환 (사용 많은 순) |
| `share_paper` | 메타데이터, 요약 5항목, 한줄요약, 연구유형, 태그, 관련연구주제, 추천코멘트, 추가메모(선택) | 없으면 페이지 생성 / 있으면 코멘트 줄 추가 + 공유자 추가 + 태그 합치기 + 최근공유일 갱신 |
| `search_papers` | 관련연구주제, 태그[], 키워드, 연구유형, 공유자, 기간 (모두 선택) | 조건을 노션 필터로 바꿔 조회 → 제목, 한줄요약, 태그, 연구주제, 공유자, 링크 목록 반환 (최대 30건) |

**`search_papers` 조회 방식**
- 관련연구주제·연구유형: Select 정확히 일치
- 태그: Multi-select 포함 (여러 개면 OR)
- 키워드: 제목·한줄요약·태그 중 하나라도 포함
- 기간: 최근공유일 기준
- 결과를 고르고 설명하는 건 사용자의 Claude가 함 (서버는 목록만 반환)
- 의미 검색("비슷한 주제")은 약함 → 논문이 많아지면 임베딩 검색 추가 검토

**서버가 강제하는 규칙** (노션은 제약조건이 없으므로)
- PMID/DOI 둘 다 없으면 거절
- PMID → DOI 순으로 중복 검사, 있으면 새 페이지 대신 기존 페이지에 추가
- 같은 사람이 같은 논문을 두 번 공유하면 거절
- 추천코멘트 비어 있으면 거절
- 관련연구주제 비어 있으면 `기타`
- 태그 소문자·앞뒤 공백 정리
- 이 DB 외의 노션 페이지에는 접근하지 않음 (통합도 이 DB에만 연결)

**서버 설정값(비밀값, 레포에는 포함하지 않음)**
- `NOTION_TOKEN`: 소유자가 만든 내부 통합 토큰
- `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY`: Edge Function이 자동으로 주입받음
- `team_members` 테이블: API 키 해시(SHA-256) → 이름

## 5. 주간 다이제스트 (Teams)

**흐름**
1. (예정) Supabase 스케줄(pg_cron)이 `paper-share-digest` 함수를 주기 실행
2. 함수가 노션 DB에서 최근공유일 지난 7일 페이지 조회
3. 관련연구주제별로 묶어 어댑티브 카드 생성 (LLM 없이 코드로 생성)
4. Teams Workflows 웹훅 URL로 POST → 채널에 게시

**메시지 형식**: 어댑티브 카드(Adaptive Card) JSON. Teams의 "Teams 웹후크 요청이 수신된 경우" 트리거는 일반 텍스트가 아니라 어댑티브 카드 형식의 요청 바디를 기대하므로, 단순 `{"text": "..."}` 대신 `TextBlock` 배열로 구성한 카드를 보낸다.

- 0편인 주는 게시하지 않음
- 노션 "이번 주" 뷰 링크를 맨 아래에 첨부

**진행 상태**: Edge Function과 어댑티브 카드 생성까지는 완성·테스트(`dry_run=1`)했으나, 기관(yuhs.ac) Power Automate 환경이 익명 웹훅 호출에 OAuth 인증을 요구해(`DirectApiAuthorizationRequired`) 실제 게시는 보완이 더 필요한 상태. pg_cron 스케줄 등록도 이 보완 이후 진행 예정.

## 6. 소유자에게 부탁할 것 (1회)

1. 노션 내부 통합 생성 (읽기·쓰기·삽입 권한)
2. 논문 공유 DB 페이지에서 그 통합을 연결
3. 토큰 전달 → 서버 환경변수(Supabase Edge Function Secrets)에만 저장
